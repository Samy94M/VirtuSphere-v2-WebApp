This is the machine API surface. Preserve wire fields and status semantics for MECM, PowerShell and Ansible. Harden with prepared statements and explicit methods, but do not remove endpoints without an E3 retirement decision. The desktop token API is retired (ADR-0035): its paths answer 404 by wire contract (`MachineApiWireTest`), and `db_importMAC.php` requires `job_id`. Its strict V2 result is additive and needs exact VM/WDS matching, an export-capable active job, current attempt/runtime/remote-handle generation and the semantic callback fingerprint under the fixed lock order. Historical V1 remains readable; only an identical replay of the same active execution is 200/no-op, while conflicts and terminal replays are 409 without domain writes. ADR-0019 candidates 1-3 and 5 remain open and need their own decisions.

MECM receives the frozen rollout hostname, never the ESXi VM name (ADR-0043). `getDeviceList` has no `SELECT *`: the projection is `VIRTUSPHERE_MECM_DEVICE_LIST_COLUMNS`, walked against the live payload in both directions by `MachineApiWireTest`, because a star had been promoting every new `deploy_vms` column to a wire field by accident. `vm_name` stays the ESXi identity, the wire key `vm_hostname` is aliased onto `mecm_rollout_hostname` (the value THIS rollout was handed, never the current portal desired value), and `rollout_revision` plus `previous_resource_id` are additive; an internal column name never leaves the database. `getDeviceInfos` stays the exact minimal contract and gains exactly `rollout_revision`.

Every mutating callback passes the revision fence under the SAME TRANSACTION as its write. The transaction is the load-bearing part, not the `FOR UPDATE`: these endpoints run in autocommit, where MySQL ends the implicit transaction of a bare locking SELECT at the end of that statement and releases the lock with it, so a reset committing in the gap would be overwritten by exactly the stale caller the fence exists to stop. Nothing inside that transaction may call `machine_api_json()`: it is `never` and ends the process, which rolls the transaction back, so a success answered from in there discards its own write. The closure decides, the answers are given outside it, and the refusal's audit row is written outside too. `mecm_rollout_fence_decide()` is pure and has three answers: current writes, current-with-the-same-binding is an idempotent 200 with no second write and no second status event, and everything else - missing, older, newer, or a different ResourceID over an existing binding - is 409 with no domain write. A future revision is refused as firmly as an old one. The pre-cutover branch accepts a missing revision ONLY for revision 1 with no tombstone; removing it after a proven cutover is its own E3/ADR decision. ADR-0019 candidates 1-3 and 5 remain open and need their own decisions.
