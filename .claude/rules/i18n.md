Portal i18n follows ADR-0014.

- German (`de`) is the default locale and English (`en`) is the second supported locale.
- Every language module must expose the same keys in `de` and `en`; run `php scripts/lang-audit.php --ci` after edits.
- Keys use the Lager-style `module.key` convention through `__t('module.key')`. The module is the catalog filename, so splitting a catalog that outgrew the 400-line budget renames every key it holds: cut along a renderer that already has its own file (`lib/help/system_status.php` owns `lang/{de,en}/help_system_status.php`), move both locales in one step, and re-render the page to check for keys echoing themselves. Watch for keys a renderer builds at runtime (`__t('help_system_status.esxi_cause_fix_' . $code)`); a grep for literals will not find them.
- A test that scans catalogs must glob them per locale (`lang/<locale>/help*.php`), never list filenames. `InventoryQueryVocabularyContractTest` listed `lang/de/help.php` and went red the moment the catalog was split, for a vocabulary that had not moved out of the help at all: which module holds a sentence is a layout decision, "the help teaches this word" is the contract. The rule covers the browser layer too: `health-matrix.spec.js` derives its key prefixes from the catalog filenames (`fs.readdirSync` over `lang/de/`) and fails when the derivation comes back empty, because an empty prefix list makes its regex unsatisfiable and the check permanently, silently green. Its hardcoded predecessor had lost four catalogs, `help_system_status` among them, whose keys `help.php` renders. That spec scans only the locale the browser negotiates; the other one is covered by the parity audit, not by a second pass.
- Locale is display-only. Do not use locale for auth, RBAC, deploy decisions, status transitions or machine API wire contracts.
- Missing translations should be visible during development rather than silently falling back to unrelated prose.
- No em dash (`—`) in user-facing prose (help, hints, explanations, flash messages) in either locale; use colon, semicolon, comma or a new sentence instead. The em dash is only allowed as an empty-value placeholder in table cells.
- Never write out a number a constant owns (a limit, timeout, interval, threshold, retention window). Put a placeholder in the text and pass the constant at the call site, in both locales. A hardcoded number keeps working while it quietly starts lying, which is why `scripts/check-bounds-sync.php` fails the build on one; a number the project genuinely does not own (the NetBIOS 15, a VARCHAR width) goes in that script's `BOUNDS_EXEMPT` with its reason. Placeholders must match across DE and EN, or one locale silently drops the number.
