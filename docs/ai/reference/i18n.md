# i18n implementation reference

Read only the owner sections relevant to the change. These detailed contracts are shared by all agent adapters. Paths refer to the repository or Docker/WebAPI as in the source contract. Commands in the reference identify underlying checks; the public execution entry remains scripts/check.ps1 according to AGENTS.md and docs/QA.md.

## R1 Portal i18n follows ADR-0014.

Portal i18n follows ADR-0014.

## R2 German (de) is the default locale and English (en) is the second supported locale.

- German (`de`) is the default locale and English (`en`) is the second supported locale.

## R3 Every language module must expose the same keys in de and en; run php scripts/lang-audit.php --

- Every language module must expose the same keys in `de` and `en`; run `php scripts/lang-audit.php --ci` after edits.

## R4 Keys use the Lager-style module.key convention through __t('module.key'). The module is the cat

- Keys use the Lager-style `module.key` convention through `__t('module.key')`. The module is the catalog filename, so splitting a catalog that outgrew the 400-line budget renames every key it holds: cut along a renderer that already has its own file (`lib/help/system_status.php` owns `lang/{de,en}/help_system_status.php`), move both locales in one step, and re-render the page to check for keys echoing themselves. Watch for keys a renderer builds at runtime (`__t('help_system_status.esxi_cause_fix_' . $code)`); a grep for literals will not find them.

## R5 A test that scans catalogs must glob them per locale (lang/<locale>/help*.php), never list file

- A test that scans catalogs must glob them per locale (`lang/<locale>/help*.php`), never list filenames. `InventoryQueryVocabularyContractTest` listed `lang/de/help.php` and went red the moment the catalog was split, for a vocabulary that had not moved out of the help at all: which module holds a sentence is a layout decision, "the help teaches this word" is the contract. The rule covers the browser layer too: `health-matrix.spec.js` derives its key prefixes from the catalog filenames (`fs.readdirSync` over `lang/de/`) and fails when the derivation comes back empty, because an empty prefix list makes its regex unsatisfiable and the check permanently, silently green. Its hardcoded predecessor had lost four catalogs, `help_system_status` among them, whose keys `help.php` renders. That spec scans only the locale the browser negotiates; the other one is covered by the parity audit, not by a second pass.

## R6 Locale is display-only. Do not use locale for auth, RBAC, deploy decisions, status transitions

- Locale is display-only. Do not use locale for auth, RBAC, deploy decisions, status transitions or machine API wire contracts.

## R7 Missing translations should be visible during development rather than silently falling back to

- Missing translations should be visible during development rather than silently falling back to unrelated prose.

## R8 No em dash (—) in user-facing prose (help, hints, explanations, flash messages) in either local

- No em dash (`—`) in user-facing prose (help, hints, explanations, flash messages) in either locale; use colon, semicolon, comma or a new sentence instead. The em dash is only allowed as an empty-value placeholder in table cells.

## R9 Never write out a number a constant owns (a limit, timeout, interval, threshold, retention wind

- Never write out a number a constant owns (a limit, timeout, interval, threshold, retention window). Put a placeholder in the text and pass the constant at the call site, in both locales. A hardcoded number keeps working while it quietly starts lying, which is why `scripts/check-bounds-sync.php` fails the build on one; a number the project genuinely does not own (the NetBIOS 15, a VARCHAR width) goes in that script's `BOUNDS_EXEMPT` with its reason. Placeholders must match across DE and EN, or one locale silently drops the number. `Lang::replace()` fills them in one pass, longest name first, so `:page` and `:pages` may share a text and a filled-in value is never searched again.
- The same holds for a list of deploy modes in a sentence ("only in the modes ..."): pass `deploy_mode_label_list()` from `lib/deploy_mode_labels.php` over the constant or predicate that decides the behaviour (`VIRTUSPHERE_DEPLOY_STAGGER_MODES`, `deploy_mode_requires_wds_ready()`, `ansible_modes_using_start()`, ...), and name a single mode only by its `status.mode_*` display label. This focused module loads its language and predicate owners and is shared by portal views and input validation without importing badge renderers into CLI paths. `virtusphere_deploy_mode_labels()` is the technical validation set and never visible text. `DeployModeTextTest` derives every list and fails on a hand-written mode name or a technical label that differs from the localized one.

## R10 Audit log sentences are rendered per viewer locale from the structured row, not translated in storage

- Audit log sentences live in `lang/{de,en}/audit_log.php`; the logs page renders a structured row in the viewer's locale (`audit_log_display_message()`, `lib/audit_log_view.php`), while the stored `log_message` stays English and canonical because the writers call the presenter with `'en'` and search, the CSV export and the saved filters read it.

## R11 German catalog values quote with the German pair „…“ only

- A value in `lang/de/*.php` quotes with `„` (U+201E) and closes with `“` (U+201C). A straight ASCII `"`, an English closing `”` (U+201D), an unclosed pair, a closing mark without an opening one and a second opening mark inside an open pair are findings of `[lang-audit.quote-mix]` in `scripts/lang-audit.php` (gate `lang-parity`, guard-harness cases `lang-audit.quote-mix` and `lang-audit.quote-unclosed`). Text inside `<code>…</code>` or `<pre>…</pre>` is a literal and is not checked; PHP comments never reach the check because it reads the loaded values. Introduced by Welle A2 (26.10.2026), which normalised 312 marks in 22 files. The English form is R12.

## R12 English catalog values quote with the straight pair "…" only

- A value in `lang/en/*.php` quotes with the straight ASCII pair `"…"` and writes the apostrophe as a straight `'`. A typographic `“` `”` `‘` `’`, a German `„` `‚` or a French `«` `»` is a finding of `[lang-audit.quote-mix]` (detail `en: typographic quote mark U+…`), and so is an odd number of straight `"` in a value (detail `en: straight quote " is never closed`); guard-harness cases `lang-audit.quote-en-typographic` and `lang-audit.quote-en-unclosed`. Same literal exemption as R11 for `<code>…</code>` and `<pre>…</pre>`.
- Why straight: many English quotes cite a value the portal or the job log prints verbatim, or that an operator types (`"skipped"`, `":host"`, a command), and the catalog was already 86 % straight. The output stays escaped by `h()` in HTML and attributes and by `json_encode()` in payloads, so a straight quote needs no other treatment.
- Introduced on 27.10.2026, which converted 63 typographic pairs and 2 apostrophes in 15 files. Tests that pin English wording with quotes (`InventoryQueryVocabularyContractTest`, `tests/e2e/specs/work-context.spec.js`) already used the straight form; the visual targets render German and are not affected.

## R13 Stored English diagnostic texts stay English and are shown only as technical details

- `deploy_create_vm_results.error_detail`/`first_error_detail` and `deploy_jobs.terminal_reason_detail` are English diagnostic texts written by the worker (and, for a module failure, the host's own message). They are stored and transported as written, never translated, and never parsed for a decision. A person reads the closed, localized sentence of the code (`VIRTUSPHERE_CREATE_ERROR_REASON_KEYS` in `lib/deploy_create_progress_findings.php`, `deploy.terminal_reason_*`); the stored text appears verbatim only inside `<code>` in the collapsed "Technische Details" (`lib/deploy_log_outcome.php`) or, for a module failure, next to the label "Meldung des Hosts". That label depends on the origin the worker recorded (`error_detail_from_host`, migration 0067), never on comparing the text: a fallback reads "Der Host hat keine genauere Meldung geliefert.", an unrecorded origin "Gespeicherter Text:". Every stored create error code has its sentence in both locales (`CreateErrorReasonContractTest`). Introduced 29.10.2026 (E2/B8/B9, prod job 1527).
