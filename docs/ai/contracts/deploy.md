# VirtuSphere deploy contracts

Read the sections relevant to the current change. Paths below are relative to Docker/WebAPI unless they already name a repository directory. Forbidden patterns remain in GROK.md section 1; these are the constructive implementation contracts.

## A41 ESXi datacenter, datastore, portgroup and VM names are raw, case-sensitive identifiers. lib/esx

- ESXi datacenter, datastore, portgroup and VM names are raw, case-sensitive identifiers. `lib/esxi_object_names.php` owns supported-name validation and exact comparison; its folded key is diagnostic only and must never select an object, capacity value or callback target. Inventory name semantics, freshness and last observation are per kind. Datacenter derivation accepts exactly one supported semantics-2 name through the inclusive bound in `VIRTUSPHERE_ESXI_DATACENTER_DERIVATION_MAX_AGE_SECONDS`; an explicit mission value bypasses derivation.

## A42 Network validity lives in lib/vm_network_contract.php; DB scope, writer locking and active-job

- Network validity lives in `lib/vm_network_contract.php`; DB scope, writer locking and active-job checks live in `lib/repo/vm_network.php`. All interface writers preserve effective MACs and validate the proposed versioned fingerprint. General ambiguity groups the exact stored VLAN bytes, without trimming; empty detection remains trim-aware. Mission-WDS changes use the same Mission -> active Job lock path and are rejected during `running`/`cancelling`, while queued jobs remain editable for the worker recheck. General empty/exact-duplicate VLAN mappings block Create, Full, Powercycle and Export and warn for Start/Autostart. The separate exact WDS rule blocks Full/Powercycle/Export and warns for Create/Start/Autostart. Mode decisions derive from the playbook sequence, not another list.

## A43 Queue and stagger paths lock the mission, materialize the explicit selection (empty means all),

- Queue and stagger paths lock the mission, materialize the explicit selection (empty means all), run general and WDS gates, and insert in one transaction. The worker reuses the same aggregator after claim and before upload/SSH; an explicit ID that disappeared stays a blocked ID and never widens the scope. Per-VM canonical progress is mandatory. The bounded `network_preflight` result and terminal `failed/configuration_blocked` transition share one owner/status CAS; if cancellation wins, the job is `cancelled` without that result and the detail must say that no remote step started. Retry recomputes the current scope and applies precedence remote execution, identity, network, external prerequisites; it never widens a partial result to already successful VMs.

## A44 Every long-running CLI process this product makes PID 1 installs the shared stop handler from l

- Every long-running CLI process this product makes PID 1 installs the shared stop handler from `lib/worker_stop_signal.php` (ADR-0042), and it handles SIGQUIT as well as TERM/INT. Two measured facts make that mandatory: PID 1 ignores any signal it has no handler for, because the kernel applies no default action there, and this image inherits `STOPSIGNAL SIGQUIT` from `php:*-fpm`. Without it `docker stop` sat out its whole grace and SIGKILLed the worker mid-playbook (30.4 s, exit 137, versus 0.4 s and exit 0 after). Never keep a second signal list, never wrap a container command in a shell (the shell becomes PID 1 and forwards nothing), and never let an idle loop wait in an uninterruptible `sleep()` — use `worker_idle_wait()`.

## A45 The supervised process shape (ADR-0042) never starts a second child before waitpid confirms the

- The supervised process shape (ADR-0042) never starts a second child before `waitpid` confirms the old one is gone, and a child that survives TERM and KILL ends in `manual`, never in a replacement: a second process would run the same job twice and create the same VM twice. Its restart decision reads the child's liveness FILE and never the database, because a worker sitting out a database outage is healthy by explicit decision. Compose keeps starting the worker; the supervised shape is `docker-compose.supervisor.yml` plus an audited contract switch, and the snapshot fails closed to `degraded` while shape and stored contract disagree.

## A46 Creating VMs is one worker-driven unit per VM (ADR-0041), never one call over a loop. The queue

- Creating VMs is one worker-driven unit per VM (ADR-0041), never one call over a loop. The queue materializes one durable `deploy_create_vm_results` row per VM in the job's own transaction, ordered by `vm_name, id`; position is the identity a portal, a log line and a retry share. Create is not a step of `ansible_remote_steps()`: the worker drives Prepare/Launch/Status/Cleanup per unit, starts exactly one `vmware_guest` call with `async`/`poll: 0`, and polls the job id in the DERIVED `create.vm.<position>/async` directory rather than a second stored copy. Terminality is the job id plus the live identity read back, never the launch result file, and never the module's verdict: `async_status` answers a vanished id with `finished` and no `failed`, so the decision hangs off the status file. The next unit starts only when no row is `prepared`, `running` or `uncertain`, read from the rows and not from process memory. `uncertain` is not a softer `failed`; it stops the job, blocks retry (`retry_create_unresolved`), and is lifted only by the release whose evidence is an inventory pull strictly newer than both job and unit with neither name nor stored UUID present. Never add a second create path or a name-based recreate.

## A47 Preflight findings are bounded in one owner, lib/deploy_preflight_bounds.php, and only for pres

- Preflight findings are bounded in one owner, `lib/deploy_preflight_bounds.php`, and only for presentation or storage. A bounded list carries the complete `total` plus what it omitted, candidate groups add `candidate_total`/`candidate_omitted_count`, and selection runs on the canonical total order that ends in binary comparisons of the exact stored bytes. An encoded island above `VIRTUSPHERE_DEPLOY_PREFLIGHT_JSON_MAX_BYTES` loses entries from the END of that order and sets `truncated_by_bytes`; the stored worker result is bounded the same way and never refused, because throwing there labels a `configuration_blocked` job `execution_failed`. `VIRTUSPHERE_DEPLOY_JOB_SCOPE_MAX_VMS` and `VIRTUSPHERE_DEPLOY_JOB_SCOPE_MAX_INTERFACES_PER_VM` cap one job's scope before any remote work, because above them a legal V2 callback can exceed its 1 MiB bound after the playbook already created the VMs. `virtusphere_bounded_utf8_bytes()` is the one UTF-8 safe byte limiter.

## A48 MAC callback V2 is strict and additive: exact VM/WDS resolution, export-capable mode, active ru

- MAC callback V2 is strict and additive: exact VM/WDS resolution, export-capable mode, active `running`/`cancelling` status, current attempt/runtime generation and the applicable current remote export handle under the Mission -> Job -> Runtime -> Handle -> VM -> Interfaces lock order. Its fingerprint includes the sorted expected VM IDs plus sorted normalized semantic rows with multiplicity; key/list order and allowlisted diagnostic metadata or free error text do not change it. Callback expectations have their own playbook-derived registry, separate from remote-mode activation. Only a semantically identical replay of that same active execution is 200/no-op; different, unreadable or terminal duplicates are 409. V1 stays historically readable. Do not change the request envelope, legacy error meanings or the five machine status strings.
