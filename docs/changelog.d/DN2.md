- **Eigener Name der Systemplatte wird zur Bezeichnung des Windows-Laufwerks (DN2, 09.11.2026).** Trägt die erste Platte einer VM im VM-Editor einen eigenen Namen, setzt `client_VMDisksOnline.ps1` ihn nach der Task Sequence als Bezeichnung des Windows-Laufwerks; ist das Feld leer, bleibt die Bezeichnung der Task Sequence. Das Feld ist für neue VMs leer und zeigt „Windows“ nur als Platzhalter, der nie gespeichert wird. Die gespeicherte Altvorgabe „System“ und Vorgabenamen wie „Disk 2“ zählen an der Systemplatte als leer; eine Migration gibt es nicht. Die Regel liegt jetzt in einer Funktion (`vm_disk_stored_name()`), die Editor, Validator, Import, Kopie, Konfliktvergleich und Maschinen-API gemeinsam nutzen; ein statischer Test lehnt neue Kopien ab. Am Feld erscheint ein Satz nur, wenn der Name gekürzt wird, Zeichen ersetzt werden oder kein verwendbares Zeichen bleibt (neue Hinweisart `system_fallback`). `getDeviceInfos` liefert je Platte zusätzlich `label_custom` (ADR-0019 Nachtrag 7); ein Client benennt das Laufwerk nur, wenn das Kennzeichen wahr ist, also nie gegen ein älteres Portal. Der Client liest die Bezeichnung vorher, setzt sie nur bei Abweichung, liest nach, merkt sich die Rolloutrevision am Schlüssel `VMDiskManagement` und überschreibt im selben Rollout keine später von Hand geänderte Bezeichnung. Das Ergebnis steht als `system=renamed|kept|skip:<Grund>` im Detail der Phase; ein Fehlschlag ist eine Warnung, die Phase bleibt erfolgreich. Nur Windows-Gäste; Datenplatten verhalten sich unverändert.
  Rollout: Das Client-Skript ändert sich, das MECM-Paket `client_VMDisksOnline` muss neu gebaut und verteilt werden. Reihenfolge: zuerst das Portal, dann das Client-Paket; ein neuer Client gegen ein älteres Portal benennt nichts um (`skip:portal_without_system_label`).
